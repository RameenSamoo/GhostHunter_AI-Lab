# Ghost Hunter 2D

A real-time 2D horror game for **AL-2002 Artificial Intelligence Lab**. You hunt
an invisible ghost through a dark stone maze using a noisy heat sensor. A Hidden
Markov Model turns every reading into a glowing probability map of where the
ghost probably is. You can hunt alone, or against **Sir Nadeem**, an AI agent that
plays by exactly the same rules.

Built with Python, Pygame (pygame-ce) and NumPy. All sprites and sounds are generated by
code, so there are no third-party assets.

---

## Setup (Windows)

1. Install **Python 3.12, 3.13 or 3.14** from python.org. On the first installer screen,
   tick **"Add python.exe to PATH"**.
2. Open this folder in VS Code, then open a terminal (`Ctrl + ``):

   ```
   py -m venv .venv
   .venv\Scripts\activate
   pip install -r requirements.txt
   python main.py
   ```

On macOS/Linux, use `python3 -m venv .venv` and `source .venv/bin/activate`.

> **Why pygame-ce?** The original `pygame` package has no ready-made build for
> Python 3.14, so pip tries to compile it and fails. `pygame-ce` is the actively
> maintained community edition: same API, same `import pygame`. Don't install both
> in one environment, because they overwrite each other.

The first launch creates `assets/` (PNG sprites), `audio/` (WAV files) and, after
your first saved score, the SQLite database `ghost_hunter.db`.

### Command-line options

| Option | Effect |
|---|---|
| `--seed 42` | Same mazes, ghost walk and sensor noise every run. Useful for repeatable demos. |
| `--mute` | Start without sound |
| `--regen-assets` | Rebuild every sprite and sound |

### Run the tests

```
pip install pytest
python -m pytest
```

## Game modes

After **Play**, pick a mode, then a difficulty.

| Mode | How it works |
|---|---|
| **Solo** | The original game: you alone against the ghost. |
| **VS AI · Simultaneous** | You and Sir Nadeem hunt the same ghost on the same maze at the same time. He starts on the cell next to yours. When he catches the ghost, a message says so and he leaves the board; the ghost keeps moving until you catch it too. If you catch it first, you watch him finish. Then both scorecards are shown. |
| **VS AI · Turn-based** | Choose who goes first. Each player hunts on the same maze from the same start cells, and the ghost walks a fresh random path each turn. A 2.5 s banner starts each turn, after which the clock runs. You watch Sir Nadeem's turn (no skip). The second player sees the first player's score as the **target to beat**. |

- **Winner:** the higher final score. The result message is shown above the two scorecards.
- **Shared controls:** P (pause), R (restart) and Quit work for the whole game in every mode, including during Sir Nadeem's turn. Restart or Quit before the end saves nothing for either player.
- **Leaderboards:** Solo, Simultaneous and Turn-based each have their own Top 5 per difficulty. VS rows show your name and score with Sir Nadeem's score from the same game. Only you enter a name; his result is saved in your row.

## How to play

| Key | Action |
|---|---|
| Arrow keys | Move one cell. Hold to run (~6 cells/s after a 200 ms delay). |
| Space | **Spirit Radar**: show the ghost on the minimap for 2 s. 3 uses per level, 5 s cooldown, −500 points each. |
| H | **A\* hint**: show the shortest path to the most likely ghost cell for 2 s. Unlimited, 5 s cooldown, −300 points each. |
| P / Esc | Pause (freezes everything) |
| R | New maze and ghost on the same difficulty |

- The ghost moves one random cell every tick, whether you move or not.
- It flickers into view for 0.3 s every few seconds.
- You catch it when you and it end up on the same cell. Passing through each other doesn't count.
- Warm floor means high probability: blue → green → amber → red.
- The heartbeat speeds up as the sensor reading drops.

### Difficulties

| Tier | Grid | Ghost moves every | Walls | Flicker every | Multiplier |
|---|---|---|---|---|---|
| Beginner | 8×8 | 1.0 s | 10% | 5–8 s | ×1.0 |
| Intermediate | 12×12 | 0.8 s | 15% | 7–10 s | ×1.5 |
| Professional | 18×18 | 0.6 s | 18% | 9–13 s | ×2.0 |
| Expert | 25×25 | 0.4 s | 20% | 11–16 s | ×3.0 |

### Scoring

```
Base   = max(0, 10000 − 50 × seconds − 20 × moves)
Scaled = Base × multiplier
Final  = Scaled − 500 × radar uses − 300 × hint uses      (can be negative)
```

Time is rounded to 0.1 s, the same precision shown on screen, so the victory
breakdown can be checked by hand. The final score rounds half up.

## AI concepts, and where to find them

### 1. Intelligent agent and environment (PEAS): `core/agents.py`, `core/grid.py`

| | |
|---|---|
| **Performance** | Final score: fast catch, few moves, few radar/hint uses |
| **Environment** | `GridEnvironment`: walls, hunter, invisible random-walk ghost |
| **Actuators** | `Action.UP / DOWN / LEFT / RIGHT` |
| **Sensors** | Own position, noisy walking-distance reading, occasional sighting (`Percept`) |

The game loop only calls `agent.act(percept, dt)`. The keyboard player is one
`HunterAgent`, and an autonomous AI hunter can be dropped in the same way.

### 2. Hidden Markov Model: `core/hmm.py`

- **Hidden state:** the ghost's cell (the walkable cells only).
- **Transition:** `T[i, j] = 1/deg(i)` for open neighbours, with no self-loops because the ghost always moves.
- **Emission:** `L(obs | g) = exp(−(obs − d_BFS(hunter, g))² / 2σ²) + ε`, with σ = 1.5 and ε = 1e-4.
- **Predict** `b ← Tᵀb` runs on ghost ticks only.
- **Update** `b ← b · L` runs on every new reading, after either the ghost or the hunter moves.
- **Exclude:** after a move with no catch, the hunter's cell gets probability 0. "I'm standing here and didn't catch it" is evidence.
- **Collapse:** while the ghost is visible (flicker or radar), the belief becomes one-hot. That's a perfect sensor.

### 3. Breadth-first search: `core/search.py`, `core/grid.py`

- Checks connectivity during map generation (CSP constraint C2).
- Builds the all-pairs walking-distance matrix used by the sensor and the emission model.

### 4. A\* search: `core/search.py`

- The heuristic is **Manhattan distance**. With orthogonal moves of cost 1, it is admissible and consistent, so the path is optimal.
- Ties are broken by smaller h, then insertion order.
- The HUD shows path length and nodes expanded while a hint is active.
- A test checks that A* path length always equals the BFS distance.

### 5. Constraint Satisfaction Problem: `core/csp.py`

- **Variables:** `X(r,c) ∈ {WALL, FLOOR}` for every cell, plus `H` and `G` (the spawn cells) ∈ FLOOR cells.
- **Constraints:**
  - C1: exactly round(density × N²) walls
  - C2: all floor cells connected
  - C3: H and G are on floor cells
  - C4: H ≠ G
  - C5: Manhattan(H, G) ≥ ⌊N/2⌋
  - VS-simultaneous adds Sir Nadeem's spawn `P`:
    - C6: P is next to H
    - C7: P ≠ G and Manhattan(P, G) ≥ ⌊N/2⌋
- **Wall stage:** constraint checking with undo. Each tentative wall is checked against C2 immediately and undone if it breaks connectivity.
- **Spawn stage:** backtracking with forward checking. G's domain is pruned for each choice of H (and P), and an empty domain triggers a backtrack. P is tried below, above, right, then left of H, so with H = (3,3) he starts at (4,3) whenever that's valid.
- Stats (assignments, undos, backtracks) are recorded in `CSPStats`.

### 6. Autonomous agent, Sir Nadeem: `core/ai_agent.py`

**Agent type:** a goal-based agent with an internal model. It runs the agent
cycle every frame, built only from the concepts above:

1. **Perceive.** The same `Percept` you get: its own cell, its own noisy reading (taken from its own position), a sighting only while the ghost visibly flickers, and where the other hunter stands.
2. **Update model.** Its own HMM forward filter: predict on ghost ticks, Bayes update on each reading, rule out its own cell, collapse onto the ghost when it flickers.
3. **Goal.** The most probable ghost cell (argmax of its belief).
4. **Plan.** A* with the Manhattan heuristic, treating your cell as blocked. It re-plans before every step, because the belief changes every tick.
5. **Act.** The first step of the plan.

**Same rules as you:**
- Walls block it, and it moves up/down/left/right only.
- Its step timer works exactly like your held arrow key: at most 6 cells/s. Tests check it is never faster than the keyboard at any frame rate.
- It never sees the ghost's true position outside flickers, gets no benefit from your radar, and never uses the radar or hints.

**PEAS:**

| | |
|---|---|
| **Performance** | Final score (same formula) |
| **Environment** | Same maze and ghost |
| **Actuators** | 4 moves |
| **Sensors** | Own position, own noisy reading, flickers, other hunter's cell |

**Measured performance** (50 games per difficulty, playing alone):

| Difficulty | Caught | Median time | Median moves | Median score |
|---|---|---|---|---|

## Design decisions

These close the gaps left open by the original spec:

1. **Catch rule.** Each frame, the hunter's and ghost's moves are computed from the old state and applied together. It's a catch only if they end up on the same cell. That makes a swap never a catch, and a ghost walking into the hunter always a catch.
2. **Predict vs update.** Prediction runs only when the ghost moves. A hunter step triggers a sensor update only.
3. **Sightings.** A flicker or radar reveal collapses the belief onto the ghost's cell, so the heat map never contradicts what the player sees.
4. **Heartbeat.** Driven by the latest noisy reading, never the ghost's true position. No ground truth leaks outside the HMM.
5. **Hotkeys.** The screen is a state machine. During name entry only text, Backspace, Enter and Esc are handled, so Space/R/P/H just type letters.
6. **High scores.** SQLite (`ghost_hunter.db`: `players`, `games`, `results` tables), Top 5 per tier. The first time the database is created, an existing `highscores.json` is imported once and left untouched. Ties go to the faster time. Negative scores qualify only while a tier has fewer than 5 entries.
7. **Sprites.** Drawn procedurally in code and saved to `assets/`, so no image tool is needed and every pixel is explainable.
8. **Pause.** Freezes the clock, ghost ticks, flicker timers and all cooldowns. Held keys are released so nothing moves on resume.
9. **Reproducibility.** One seeded RNG drives maze generation, ghost moves and sensor noise.
10. **VS movement.** Hunters block each other. A move onto the cell the other hunter stands on at the start of the frame is blocked, and so is a swap. If both step into the same empty cell, you get it. Blocked moves cost nothing, like walls.
11. **VS information.** The heat map, PKE reading and heartbeat are yours only. Sir Nadeem keeps his own belief and sensor internally, and it's never displayed.
12. **Caught hunters leave the board.** In simultaneous mode, whoever catches the ghost first disappears; the ghost and the other hunter carry on. The light follows whoever is still hunting.
13. **Flat-belief colouring.** Before the first reading the belief is uniform, so the heat map shows no warm cells. Previously every cell tied for "hottest" and the maze flashed red for up to a second at the start.
